# th-modelgw

Внутренний FastAPI-шлюз к OpenRouter. `POST /api/v1/inference` выполняет оценку риска, черновик документа, эмбеддинги или разбор изображения. `GET /healthz` проверяет запуск приложения, `/docs` содержит схему API.

## Запуск

Укажите `OPENROUTER_API_KEY` и `OPENROUTER_MODEL_TEST` в корневом `.env`. Из корня репозитория выполните:

```sh
docker compose --env-file .env.example --env-file .env up --build --wait th-modelgw
```

Compose запустит шлюз и Redis. Адрес с хоста по умолчанию `http://127.0.0.1:8001`, внутри Compose `http://th-modelgw:8000`. Порт хоста задаётся через `MODEL_GW_HOST_PORT` в корневом `.env`. Для настройки таймаутов, TTL, версии промпта и отдельных моделей скопируйте [пример настроек сервиса](.env.example) в `.env` внутри `services/th-modelgw` и измените нужные поля. Ошибочная конфигурация приводит к отказу запуска. Для разработки с хоста Redis URL должен указывать на опубликованный порт Redis.

`OPENROUTER_MODEL_TEST` используется для `risk_assessment` и `document_draft`. Модель должна поддерживать JSON-ответы. Для рабочих запросов требуется маршрут с `data_collection=deny`. Для `embeddings` и `vision` укажите `MODEL_GW_EMBEDDINGS_MODEL` и `MODEL_GW_VISION_MODEL` соответственно. Шлюз вернёт `503 task_disabled`, если модель задачи не настроена. Для смены провайдера достаточно заменить адаптер `ModelProvider` и настройки в композиции.

## Контракт

Пример `POST /api/v1/inference`:

```json
{
  "job_id": "d948fa35-8771-49da-aebb-282049356694",
  "task": "risk_assessment",
  "context": [
    {"type": "synthetic_text", "text": "The delivery date is specified in the public notice."},
    {"type": "knowledge", "rules_version": "kb-v1", "penalty_daily_threshold_percent": "0.1"},
    {"type": "penalty", "daily_percent": "0.15"}
  ],
  "prompt_version": "v1",
  "mask": true
}
```

- `public_text` принимает публичный или предварительно обезличенный текст, который вызывающий сервис проверил перед отправкой. Шлюз нормализует его и дополнительно маскирует распознаваемые персональные, регистрационные, банковские, организационные и коммерческие сведения. При остаточном подозрительном шаблоне возвращается `422 unsafe_context`. Поля `sensitive_text` с категорией `personal`, `organization`, `registration`, `banking` или `commercial` полностью исключаются перед вызовом. Необработанные тендерные документы должны пройти классификацию и обезличивание на стороне источника.
- Для проверки бесплатной модели на вымышленных данных укажите `type: "synthetic_text"` вместо `public_text`. В локальном Compose `MODEL_GW_SYNTHETIC_PROVIDER_COLLECTION=true` допускает `data_collection=allow`, когда весь текст для провайдера синтетический и изображений нет. Смешанный и рабочий контекст используют `deny`. Применяйте тестовый тип только к вымышленным примерам.
- Для `risk_assessment` передайте по одному `knowledge` и `penalty`. Они обрабатываются локально. До появления API `th-kb` вызывающий сервис передаёт версию знаний и порог правила `R-RISK-04`, а извлечённое значение берёт из нормализованного результата обработки документов. `0.15` означает 0,15% в день. Модель возвращает гипотезу с индексами публичных фрагментов. При конфликте действует локальное правило и итоговая уверенность становится `0`. `answer.human_reason` передаёт `penalty_above_threshold` или `unclear_requirements` оркестратору, который владеет `HumanDecision`.
- Для `document_draft` и `embeddings` нужен хотя бы один `public_text` или `synthetic_text`. Векторы возвращаются в порядке переданных фрагментов. `confidence=1` для эмбеддингов означает, что количество и размерность векторов прошли проверку.
- Для `vision` нужен один `public_image` с `data` в виде base64 PNG или JPEG. Вызывающий сервис должен проверить и обезличить пиксели до передачи. Шлюз принимает до 2 МБ и 4 млн пикселей, перекодирует изображение без метаданных и отправляет его без внешних ссылок. Дополнительные `public_text` описывают задачу.

Успех возвращает `job_id`, `answer`, `confidence`, фактическую `model_version`, `prompt_version`, `masked` и `trace_id`. Для ошибок доступны `code` и `trace_id`. `422` означает ошибку входа, `502` отказ провайдера или невалидный ответ, `503` недоступность провайдера или выключенную задачу, `504` исчерпанные попытки при таймауте.

Redis хранит только проверенные ответы модели с TTL. Ключ учитывает версию промпта, модель, задачу и подготовленный публичный контекст. Локальное правило проверяется заново при попадании в кэш. При сбое Redis запрос обрабатывается без кэша. В логи попадают идентификаторы, версии, длительность и исход запроса. Текст, изображения, исходные ответы и ключ OpenRouter в трассировку не записываются.
