# th-solver — ядро решателя TenderHive

Преобразует извлечённые требования и факты в проверяемую рекомендацию. Стек: продукционные правила, RAG-контекст из `th-kb` и ограниченный вызов `th-modelgw`. В сервисе нет формального логического вывода, деревьев доказательств и машин вывода. Сервис не принимает файлы, не хранит версии знаний и не формирует карточки HITL.

## API

| Метод и путь | Назначение |
| --- | --- |
| `POST /api/v1/solve` | Принять `SolveRequest` (`job_id`, `kb_version`, `requirements`, `facts`, `profile`, `lot_ids`, `trace_id`) и вернуть `SolverResult` |
| `GET /healthz` | Готовность процесса |

Результат содержит `status` (`READY | INCOMPLETE | NO_SOLUTION`), требования, проверку соответствия, ресурсы, смету, риски, рекомендацию, план подготовки предложения, объяснение со ссылками на правила и источники, описания артефактов DOCX/PDF/XLSX и `stop_reasons`. Вычисление отделено от представления: артефакты формирует агент-генератор в `th-agents`, событие публикует `th-orchestrator`.

## Логика

1. Запросить контекст зафиксированной версии знаний в `th-kb` и отклонить подмену версии.
2. Применить продукционные правила к фактам; индекс по ключу факта даёт `O(|F| + |R|)`. Конфликт правил с одинаковым приоритетом и разными следствиями не разрешается молча — он попадает в `stop_reasons`.
3. Подобрать фрагменты корпуса и связи через `th-kb` (Qdrant, Neo4j).
4. Оценить пеню через `th-modelgw`; гипотеза модели остаётся предположением, итоговое решение принимает правило или человек.
5. Проверить пороги маржи и пени, покрытие ресурсов и уверенность извлечения; сформировать `stop_reasons` для точек HITL.
6. Собрать результат и трассировку, связав каждое следствие с правилом, версией и источником. Успешный результат кэшируется в Redis по хешу запроса и версии знаний.

`requirements` принимает общий формат `th-docintel`, включая структурированный `source`, `unit`, `needs_review` и `template_set_version`. Значения с единицей `fraction` (`0.0015` = 0,15 %) преобразуются в проценты только при передаче в `th-modelgw`; требование с `needs_review=true` не отправляется модели и вызывает эскалацию.

Адреса хранилищ, пороги, TTL и таймауты задаются в [`.env.example`](.env.example) с префиксом `SOLVER_`, стандартных параметров в коде нет.
