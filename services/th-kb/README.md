# th-kb — база знаний TenderHive

Хранит правила, факты, справочники, версии и тестовые входы. PostgreSQL — основное хранилище и журнал активаций, Neo4j — связи требований и ресурсов, Qdrant — текстовый корпус для RAG, Redis — только кэш активной версии с коротким TTL. Сервис не вызывает модель, не принимает решений по заданию и не принимает файлы.

## API

Базовый префикс — `/api/v1`, ошибки имеют вид `{code, message, trace_id}`, все запросы несут `X-Trace-Id`.

| Метод и путь | Назначение |
| --- | --- |
| `POST /versions` | Зарегистрировать версию со списком правил, фактов, справочников и тестовых случаев |
| `GET /versions` | Список версий со статусами |
| `GET /versions/{version}` | Карточка версии |
| `POST /versions/{version}/activate` | Проверить версию и атомарно активировать |
| `POST /versions/{version}/rollback` | Вернуть предыдущую версию без пересборки |
| `GET /context?version=…&regime=…&task_class=…&lot_ids=…&query=…` | Контекст для `th-solver`: правила, факты, срез графа и фрагменты корпуса |
| `GET /healthz` | Готовность процесса |

Контрольная сумма версии считается по каноническому JSONpayload без поля `checksum`. Перед активацией выполняются проверки: контрольная сумма, ссылочная целостность, типы значений, периоды действия, несовместимость правил с пересекающейся областью и разными следствиями, прогон тестовых случаев и сравнение с активной версией. При провале версия получает статус `REJECTED`, а ответ содержит отчёт с кодом ошибки; активная версия не меняется.

## Запуск

Настройки лежат в [`.env.example`](.env.example) (префикс `KB_`), секретов в репозитории нет. Миграция — [`migrations/001_kb.sql`](migrations/001_kb.sql).

```sh
uv sync --locked
uv run --locked python -m th_kb
```

Проверки перед коммитом:

```sh
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pyright
uv run --locked pytest
```
