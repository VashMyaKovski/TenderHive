# Карта сервисов TenderHive

Каталоги под `services/` создаются по мере реализации. Каждый сервис отвечает за свои данные и публикует API или события по [общим контрактам](../contracts/README.md).

| Каталог | Стек | Ответственность |
| --- | --- | --- |
| [`th-orchestrator/`](th-orchestrator/README.md) | Python, FastAPI, LangGraph | Состояние задания, оценка риска через A2A, ожидание ответа и эскалация |
| [`th-agents/`](th-agents/README.md) | Python, FastAPI, A2A | Оценка риска по фрагменту договора через `th-modelgw` |
| [`th-solver/`](th-solver/README.md) | Python, FastAPI | Продукционные правила, RAG, рекомендация и объяснение результата |
| [`th-kb/`](th-kb/README.md) | Python, FastAPI | Правила, факты, справочники, корпус и версии знаний. Использует PostgreSQL, Neo4j и Qdrant |
| [`th-modelgw/`](th-modelgw/README.md) | Python, FastAPI | Единый доступ к внешним моделям. Шаблоны промптов, маскирование, проверка ответов и кэш |
| [`th-eval/`](th-eval/README.md) | Python | Наборы сценариев, регрессии, метрики и бенчмарки моделей и промптов |
| [`th-integrations/`](th-integrations/README.md) | Python, MCP | Автоматический приём тендерных документов по почте и MCP-заглушки для внешних систем |
| [`th-docintel/`](th-docintel/README.md) | Python, Tesseract, C++20, gRPC | HTTP-загрузка PDF/DOCX/изображений, извлечение текста/OCR и таблиц; C++-ядро нормализует, сопоставляет шаблоны и разбирает числа |
| `th-gateway/` | C#, ASP.NET Core | Telegram-бот, загрузка файлов, авторизация, регистрация задания и выдача артефактов |
| `th-web/` | C#, Blazor | Дашборд заданий, согласования и управление базой знаний через API шлюза |

## Границы взаимодействия

- Почтовый приём и ручная загрузка создают `Job`. Оркестратор управляет этапами и точками согласования. Решатель возвращает рекомендацию и трассировку, а решение по эскалации фиксируется как `HumanDecision`.
- `th-kb` владеет хранилищами знаний. Решатель, агенты и шлюз моделей получают знания через его публичный контракт. Версия базы знаний фиксируется в задании для воспроизводимости.
- `th-orchestrator` владеет этапом `extract`, его повторами и эскалацией. Результат `th-docintel` по [общему контракту](../contracts/docintel_v1.py) потребляют `th-solver` и агент извлечения требований в `th-agents`; они не дублируют разбор PDF/DOCX и OCR.
- `th-eval` владеет наборами регрессии и метриками; его текущий CLI оценивает шлюз рисков, а контракт `docintel_v1` и отдельный C++-бенчмарк дают точки подключения для будущих прогонов извлечения.
- Внешний вызов модели проходит через `th-modelgw`. Перед отправкой шлюз маскирует персональные данные, реквизиты, банковские и регистрационные сведения и коммерчески чувствительные условия. Если безопасность полезной нагрузки подтвердить не удалось, вызов блокируется. Ключ провайдера, исходные чувствительные данные и карта замен исключаются из логов и телеметрии.
- Регистрация задания с публикацией события требует обработки повторов и согласованности с записью задания. При реализации шлюза это обеспечивается транзакционным outbox. Идемпотентность потребителей, политика повторов и dead-letter согласуются вместе со схемами событий.
