# Контракты TenderHive

`Job`, `SolverResult` и `HumanDecision` описаны как Pydantic-модели в [models.py](models.py). JSON Schema можно получить вызовом `model_json_schema()`.

Контракт подзадачи рискового агента опубликован в [risk_task_v1.py](risk_task_v1.py). Вход `RiskTaskV1`, результат `RiskResultV1` и сбой `RiskFailureV1` передаются в A2A как структурированные части `data`. [Описание API и пример](../services/th-agents/README.md)

Черновик предполагает даты с часовым поясом и строковые идентификаторы лотов. Вложенные структуры результата, для которых задание пока не задаёт поля, принимают JSON-значения. Перед подключением производителей и потребителей согласуйте их форматы и представление незавершённого решения человека.

| Тема Kafka | Назначение |
| --- | --- |
| `tender.job.created` | Зарегистрировано новое задание |
| `tender.stage.done` | Завершён этап обработки задания |
| `tender.human.required` | Требуется решение человека |
| `tender.human.decided` | Решение человека зафиксировано |
| `tender.artifacts.ready` | Артефакты готовы |

Локальные темы создаются командой `docker compose run --rm kafka-init`. Перед реализацией транспорта согласуйте схему и версию сообщений, ключ партиционирования, подтверждение доставки, повторы и обработку сообщений, которые не удалось принять.

Точки подключения событий к шагам оркестратора и предлагаемый конверт описаны в [README оркестратора](../services/th-orchestrator/README.md#точки-подключения-событий).
